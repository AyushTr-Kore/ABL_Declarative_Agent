# Speech-to-speech rules

| Area                           | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Orchestration                  | Choose `runtime_guarded` or `runtime_owned` explicitly. New realtime channel connections default to `runtime_owned`; connections created before the setting existed keep legacy behavior. Move a live agent to another mode only after an eval compare, because the mode changes which tool calls are accepted. Verify the effective mode in traces.                                                                                                                                                                                                                                  |
| Ordering and permissions       | Put ordering, field ownership, validation and confirmation in FLOW. Keep GATHER steps atomic and selection separate from confirmation. Never write a prompt line that contradicts the FLOW.                                                                                                                                                                                                                                                                                                                                                                                           |
| Tool contracts                 | Declare `effect` on every tool (`read_only`, `state_write`, `side_effect`). Use `provides` and `on_result.set` instead of context-setting calls; `process.before.require` with `on_fail: reask`; `confirm: when_side_effects` for writes.                                                                                                                                                                                                                                                                                                                                             |
| Idempotency                    | Make every write idempotent at the backend too. A dropped result can make the model call a booking tool again.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Tool results                   | Never assume the provider will voice a result on its own. Test success, error, timeout and empty payloads, with fillers on and off. Never let raw backend errors reach the speech model; map them to categories with a spoken fallback. Keep results small.                                                                                                                                                                                                                                                                                                                           |
| Blocking vs non-blocking tools | Check whether the realtime model supports asynchronous function calls. On one model, non-blocking tools with idle scheduling deadlocked.                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Filler wording                 | Never write "until the tool completes" or similar in filler or progress text; on one model it made the agent re-call the tool in most calls.                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Greeting and barge-in          | Protect the welcome and must-hear messages with `barge_in: disallow` (on the flow step or in `voice_config`); add `streaming: false` for the strongest delivery guarantee at the cost of first-audio latency. `streaming: false` alone does not protect a response from interruption. On Google realtime channels, an opening-greeting barge-in policy applies only when the channel's opening barge-in policy setting is turned on (off by default); test greeting behavior on every provider. Very short VAD prefix padding with start-of-activity interrupts can cut the greeting. |
| Fillers and dead air           | Measure silence from the end of the caller's speech before blaming fillers; VAD tuning can remove seconds of dead air. Only a caller turn should end fillers, not a handoff.                                                                                                                                                                                                                                                                                                                                                                                                          |
| Guardrails                     | In legacy and `runtime_guarded` modes, caller speech can skip input guardrails. If compliance rules must apply to what the caller says, use `runtime_owned` and verify in traces.                                                                                                                                                                                                                                                                                                                                                                                                     |
| Language                       | A language switch needs a validated multilingual voice map, the auto-switch settings and ASR and TTS entries per language. Do not hard-code a language in the prompt when callers can switch.                                                                                                                                                                                                                                                                                                                                                                                         |
| Temperature                    | Treat temperature as model-specific and a late suspect. Find the root cause in traces first. Record the value you set: it may appear only in the gateway setup, not in runtime traces. Low values truncated replies on one model; high values caused hallucination on another.                                                                                                                                                                                                                                                                                                        |
| Defaults                       | Set behavior-critical channel settings explicitly (tool scheduling, VAD, silence duration) and re-test after every platform release; a changed default can break a live flow.                                                                                                                                                                                                                                                                                                                                                                                                         |
| Model version                  | Test handoff, resume, barge-in timing and temperature on the exact model version you ship; realtime model versions behave differently.                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Evidence                       | Pull gateway logs as well as runtime traces: runtime traces can miss provider closes. Watch for a barge-in immediately after a tool result and the same tool re-dispatched within seconds; both suggest a dropped result.                                                                                                                                                                                                                                                                                                                                                             |

## Field patterns

Illustrative patterns from production speech-to-speech projects; the numbers are directional, not
benchmarks.

- After a tool returned, callers heard a progress filler and then long silences; the
  answer was spoken only when the caller asked "are you there?". The provider had no trigger to speak
  the queued result. The fix sends an explicit speak trigger after every tool result, including error
  and timeout paths, and traces each trigger.
- A caller stayed in the wrong language because the legacy orchestration mode never advanced the
  FLOW past the language step, and a prompt line contradicted the FLOW. The team had blamed
  temperature.
- Flow steps ran out of order and a partial phone number was committed because, in legacy mode, the
  model drives every tool call and the tools declared no effects or preconditions.
- A booking ran three times after a provider-generated interruption was treated as caller barge-in
  and the result was dropped; the booking path had no effective duplicate protection, so each
  re-call created a new order. Declare `effect` on write tools and make backend writes idempotent.
